2. WHAT IS GIT CLONE?
---------------------
Git cloning is the process of creating a local copy of an existing
remote Git repository.

Usually:

    GitHub Repository
           |
       git clone
           |
           v
    Local Computer

Example:

    GitHub
    └── AutomationProject
        ├── login.spec.js
        ├── signup.spec.js
        └── README.md

After cloning:

    Local Computer
    └── AutomationProject
        ├── login.spec.js
        ├── signup.spec.js
        ├── README.md
        └── .git/


3. IMPORTANT: WHAT DOES git clone ACTUALLY DO?
----------------------------------------------
git clone does more than simply download files.

It creates:

- A local copy of the project files
- A local Git repository
- Git history
- A connection to the remote repository

Example:

    git clone <repository-url>

After cloning, the local project already has a .git directory.

Therefore, normally you DO NOT need to run:

    git init

again inside the cloned project.


4. HOW TO CLONE A REPOSITORY
----------------------------
Step 1:
Go to the GitHub repository URL.

Step 2:
Click the green "Code" button.

Step 3:
Copy the repository URL.

Example:

    https://github.com/username/project.git

Step 4:
Go to the folder/location on your computer where you want the
repository to be cloned.

Step 5:
Open Git Bash in that location.

On Windows:

    Right click
        ->
    Show more options
        ->
    Git Bash Here

Step 6:
Run:

    git clone <repository-url>

Example:

    git clone https://github.com/username/project.git

Step 7:
Open the cloned folder and check the files.

Step 8:
Run:

    git status

This confirms that the folder is now a Git working repository.

9. QUICK REVISION: git add vs git add .
---------------------------------------
Specific file:

    git add login.js

Meaning:

    Stage only login.js.

All applicable changes under the current directory:

    git add .

Meaning:

    Stage all applicable changed/untracked files under the current
    directory.

Important:

    git add
        -> Staging only

    git commit
        -> Creates a local checkpoint

    git push
        -> Sends commits to GitHub


10. WHAT IS .gitignore?
-----------------------
.gitignore is a special file that tells Git which untracked files
or directories should be ignored.

Example:

    .env

If .env is listed in .gitignore, Git will normally not show that
untracked file as something to add.

Think of it as:

    .gitignore
          |
          v
    "Git, don't include these files in normal tracking."


11. WHY DO WE USE .gitignore?
-----------------------------
We usually don't want to push certain files or folders to GitHub.

Common examples:

    .env
    node_modules/
    test-results/
    playwright-report/
    cypress/screenshots/
    cypress/videos/

Reasons include:

- Secrets/passwords/API keys
- Large dependency folders
- Generated test reports
- Temporary files
- Machine-specific files
- Build output


12. HOW TO CREATE .gitignore
----------------------------
Step 1:
Create a file named exactly:

    .gitignore

It should be in the project/repository root, normally where the .git
directory exists.

Example:

    Project/
    |
    |-- .git/
    |-- .gitignore
    |-- login.js
    |-- signup.js
    `-- README.md


13. HOW TO ADD FILES TO .gitignore
----------------------------------
Simply add the file name or path.

Example:

    .env

This ignores a file named .env.

Example:

    node_modules/

This ignores the node_modules directory.

Example:

    test-results/

This ignores the test-results directory.

Example .gitignore:

    .env
    node_modules/
    test-results/
    playwright-report/


14. FILE NAME vs FILE PATH
--------------------------
You can ignore a specific file:

    secret.txt

Or a directory:

    reports/

Or a path:

    config/local.json

The pattern you write in .gitignore determines what Git ignores.

16. IMPORTANT QUESTION
----------------------
Question:

"If a file is already uploaded to GitHub and I later add that file
to .gitignore, will GitHub automatically remove it?"

Answer:

    NO.

This is very important.

.gitignore is mainly used to prevent UNTRACKED files from being added
to Git.

If a file is already tracked and committed, simply adding it to
.gitignore does NOT remove it from GitHub.


17. WHY?
--------
Think about the difference:

UNTRACKED FILE:

    File exists locally
          |
       .gitignore
          |
       Git ignores it
          |
    Not added/committed


ALREADY TRACKED FILE:

    File
     |
    git add
     |
    git commit
     |
    Git tracks it
     |
    Adding it to .gitignore later
     |
    Does NOT automatically remove tracking


18. HOW TO STOP TRACKING AN ALREADY TRACKED FILE
------------------------------------------------
If a file has already been committed and you now want Git to stop
tracking it, use:

    git rm --cached filename

Example:

    git rm --cached .env

Then add it to .gitignore:

    .env

Then commit:

    git add .gitignore
    git commit -m "Stop tracking env file"

Then push:

    git push origin main

Important:

    git rm --cached

removes the file from Git's tracking/index but keeps the local file
on your computer.


19. EXAMPLE: .env FILE
----------------------
Suppose .env was accidentally committed.

Step 1:
Add it to .gitignore:

    .env

Step 2:
Stop tracking it:

    git rm --cached .env

Step 3:
Commit the change:

    git add .gitignore
    git commit -m "Stop tracking env file"

Step 4:
Push:

    git push origin main

Now Git will stop tracking the file.

IMPORTANT SECURITY NOTE:
If the .env file contained real passwords, API keys, tokens, or other
secrets and was already pushed, adding it to .gitignore is NOT enough.
The exposed secret should be rotated/revoked, because it may still
exist in Git history.


20. IMPORTANT DIFFERENCE: CLONE vs DOWNLOAD ZIP
-----------------------------------------------
Git Clone:

    git clone <url>

Creates:
- Project files
- .git directory
- Git history
- Remote connection

Download ZIP:

    Download ZIP

Usually gives:
- Project files only
- No normal local Git history/repository connection

Therefore, for Git-based development, cloning is normally preferred.


21. IMPORTANT DIFFERENCE: git clone vs git pull
-----------------------------------------------
git clone:

    Used to get a repository for the first time.

Example:

    git clone <repository-url>


git pull:

    Used to get the latest changes into an existing local clone.

Example:

    git pull

Simple rule:

    First time -> git clone

    Already cloned -> git pull

26. INTERVIEW QUESTIONS
-----------------------
Q1. What is git clone?

A. git clone creates a local copy of an existing remote Git repository
and also sets up the local Git repository and remote connection.


Q2. What is .gitignore?

A. .gitignore specifies files and directories that Git should ignore,
so they are not normally added as untracked files.


Q3. If I add an already committed file to .gitignore, will it be
removed from GitHub?

A. No. .gitignore does not automatically remove files that Git is
already tracking.


Q4. How do you stop Git from tracking an already tracked file?

A. Use:

    git rm --cached <filename>

Then commit and push the change.


Q5. What is the difference between git clone and git pull?

A. git clone is generally used to create the first local copy of a
repository. git pull is used to get new changes into an existing clone.


Q6. Does git clone mean only downloading files?

A. No. It creates a local Git repository containing the project files,
Git history and remote configuration.


27. GOLDEN RULE
--------------

    git clone

    git pull
